# Calmspace Data Inventory & Privacy Disclosure (Issue #11)

## Status and scope

This inventory describes `feat/issue-11-privacy-controls`, based on `main`. It does not describe the separate, unmerged deployment branch. The current backend uses in-memory storage; this branch does not provide production persistence or authenticated sessions.

`backend/app/services/safety_evaluator.py` is protected and unchanged. Its required Git blob hash is `8f5e2e984c4ab41212a74a16158200b2c7a126b2`.

## Data inventory

| Data | Purpose | Current handling | Retention / disclosure |
|---|---|---|---|
| Random browser session ID | Associate check-ins, tasks, and preferences | Generated by the frontend, stored in browser `localStorage`, and sent as a required `X-Session-ID` header; missing, blank, or malformed IDs are rejected | It is not a secure login credential. Authenticated access, cross-session authorization, and credential revocation are not implemented on this branch. |
| Mood, stress, sleep, and safety route | Check-in history, trends, and deterministic safety evaluation | Stored as a check-in record in backend process memory; reflection is not part of the record | HIGH and other routes use the same fixed 30-day retention. | Optional reflection | Safety evaluation and, with consent, supportive guidance | Evaluated by Calmspace's safety rules in the request; never stored in Calmspace check-in records | A provider receives reflection only when consent is the actual boolean `true`, the result is LOW/MEDIUM, and AI is enabled/configured. HIGH-route content always bypasses AI. External provider retention is outside Calmspace's control. |
| Nickname and reminder preferences | Dashboard greeting and in-app reminders | Stored in backend process memory, associated with the browser session ID | Cleared on deletion or backend restart. Nicknames are user-provided; users should not enter identifying information. |

### Retention and deletion

- Check-in ratings and route, including HIGH-route records, have a fixed 30-day application retention window. The in-memory implementation prunes expired records whenever check-ins are read or added.
- The previously approved 90-day inactivity expiry is not implemented here: there is no authenticated session lifecycle or session activity record on this branch.
- `DELETE /api/settings/data` removes check-ins, tasks, and preferences associated with the supplied session ID. The frontend clears its saved result and session ID after server confirmation.
- High-risk Safe Exit starts deletion without delaying navigation to the overview. If deletion fails, a pending notice is shown in Settings so the user can retry.
- The current deletion endpoint is not authorization-secured. It must not be represented as secure credential revocation or used as a production privacy boundary until authenticated session controls are integrated.
- This branch has no database or application backups. Any future database/host backups and third-party AI retention require separate policy and operational configuration.

## User-facing disclosure contract

### Before check-in

Disclose the values collected, their association with a random browser session ID, current in-memory storage, restart behavior, 30-day check-in retention, and that the ID is not a secure credential. Advise users not to include direct identifiers in free text.

### Reflection and AI consent

- Reflection is optional and is never persisted in Calmspace check-in records.
- Deterministic safety rules evaluate reflection independently of AI consent.
- Consent defaults off and must be an actual boolean `true`; malformed values are rejected rather than coerced.
- With valid consent, the result must still be LOW or MEDIUM and the configured provider must be enabled for an external call to occur.
- HIGH-risk/crisis content must never be sent to an AI provider, even if consent is true.
- Deployments may configure Google Gemini. The disclosure must explain that an opted-in reflection may leave Calmspace and that Calmspace cannot control the provider's retention or deletion.

### Settings and planner

Explain that nicknames and task titles are user-provided and may reveal identity, analytics are disabled in this demo, check-in data is held in memory with fixed 30-day retention, and current session IDs are not authentication credentials. Deletion messaging must distinguish Calmspace data from data already processed by an external provider.

## Verification and remaining dependencies

Issue #11 checks on this branch cover explicit consent parsing, deterministic fallback, HIGH-route provider bypass, reflection non-persistence, fixed retention, and deletion failure behavior.

The following are not established by this branch and remain blockers for production use:

1. Integrate the authenticated session work from Issue #10 before relying on session isolation, deletion authorization, or credential invalidation.
2. Implement and verify the approved 90-day session inactivity expiry.
3. Integrate persistent storage and test deletion/migrations and retention against that store.
4. Review production host, proxy, database backup, and AI provider logging/retention policies.
